# Agent Rules

This repository is a personal, non-production NixOS flake under active
development. Prefer direct iteration and proportionate validation over formal
review ceremony.

## Scope and Safety

- Preserve unrelated user changes and keep edits within the requested scope.
- Do not stage, commit, push, merge, create branches or worktrees, or rewrite
  history unless the user explicitly asks.
- Do not decrypt secrets or expose secret values. Keep secret material managed
  through SOPS and reference its declared paths from Nix modules.
- Avoid changing machine hardware, disk, boot, or secret configuration unless it
  is directly required by the task.

## Repository Structure

- `modules/aspects.nix` discovers modules automatically with `import-tree` and
  adapts them into selectable NixOS and Home Manager aspects.
- Put application configuration in `modules/apps`, reusable system services in
  `modules/services`, composable bundles in `modules/roles`, host declarations in
  `modules/machines`, and user configuration in `modules/users`.
- Keep desktop-specific services with their desktop aspect instead of enabling
  them globally.
- Module names are derived from filenames and must be unique within the aspect or
  machine namespace.
- Prefer an aspect's `nixos` and `home` sections for system-level and user-level
  configuration respectively. Use `aspectHelpers` only for parameterized aspect
  constructors that cannot be expressed as a plain module.

## Generated Files and Inputs

- Do not edit `flake.nix` directly. It is generated by `flake-file`; declare input
  and output changes through `flake-file` options in the relevant module, then
  regenerate it with `nix run .#write-flake` when needed.
- Treat `.pre-commit-config.yaml` and `.devenv` as generated state. Change hook or
  development-shell configuration in `devenv.nix` instead.
- Update `flake.lock` only when the requested change requires an input update.

## Validation

- Run `nixfmt` on changed Nix files and run `statix check` when practical.
- At minimum, use `nix-instantiate --parse` for edited standalone Nix files and
  `git diff --check` for the final diff.
- For configuration changes, evaluate the affected host under
  `nixosConfigurations.<host>`; use `daisy` for Sway and `fern` for Plasma.
- Run broader flake checks or builds when the risk warrants them, but avoid
  rebuilding unrelated hosts for a small localized edit.
- If hooks reformat files during a requested commit, inspect the resulting diff
  before reporting completion.

## Git Conventions

- Commit messages follow Conventional Commits: `type(scope): subject`.
- Use `git commit -s` so the `Signed-off-by:` trailer is present.
- Use a lowercase imperative subject with no trailing period and a concise,
  meaningful scope such as `app`, `ui`, `tracking`, `carrier`, `auth`, `db`,
  `agents`, or `tooling`.
- Never add a `Co-authored-by:` trailer.
